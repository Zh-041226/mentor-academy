# 手机端首页聚合改版共识

## 明确需求

1. 本轮在现有 `frontend` 中新增手机端整体页面方案，采用“首页聚合型”结构。
2. 手机端一级入口收敛为 `首页`、`活动`、`公告`、`我的`，并提供底部常驻导航。
3. 首页首屏必须同时具备品牌感、活动推荐和快捷操作，优先展示当前可报名活动。
4. 不改后端接口，不新增依赖，优先复用现有活动、公告、用户信息接口与组件资源。

## 范围边界

1. 本轮重点实现手机端 H5 页面骨架与核心页面布局，不单独开发微信小程序版本。
2. 保留桌面端现有导航、活动广场、公告页和用户中心主流程，移动端在同一前端项目内做响应式增强。
3. 本轮不重做后台页面，不改活动报名接口契约，不引入新的推荐算法。
4. 默认跳过测试代码，采用构建验证与页面诊断作为本轮交付验证方式。

## 技术方案

1. 路由层新增手机端首页视图，作为“首页聚合型”主入口。
2. 组件层新增移动端底部导航、首页快捷入口、活动卡片等通用组件。
3. 页面层对 `公告`、`我的信息`、`活动详情`、`我的活动` 做手机端适配，统一按钮、卡片、间距与安全区表现。
4. 全局层通过 `App.vue` 区分桌面导航与移动端导航呈现，避免顶部固定导航在手机端挤压内容。

## 验收标准

1. 手机宽度下可看到独立的首页聚合布局，而不是桌面活动页的压缩版。
2. 手机端底部存在常驻导航，并可在 `首页`、`活动`、`公告`、`我的` 之间切换。
3. 首页包含 Banner、快捷入口、推荐活动、今日可报和分类活动区块。
4. `公告`、`我的活动`、`活动详情`、`我的信息` 在手机端均具备可读的单列卡片布局和清晰主操作按钮。
5. 项目可正常构建，新增文件无明显诊断报错。

## 已确认决策

1. 实现目标为现有 Web 前端的手机端 H5，而非 `WeChatProject` 小程序。
2. 视觉风格延续现有暖色日落主题，中文文案优先。
3. 采用“最小风险增量改造”，优先新增移动端组件与路由，不大规模推翻现有桌面逻辑。
