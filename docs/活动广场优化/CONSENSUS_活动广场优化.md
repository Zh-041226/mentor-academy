# 活动广场优化共识

## 明确的需求与范围

1. 智能推荐逻辑调整：
- 取消“收藏”权重（当前系统无收藏功能）。
- 以“过往参加的活动类型（从 /users/me/registrations 返回的类别）”作为兴趣偏好加权。
- 仅推荐当前可报名的活动（报名未截止且名额未满）。
- 推荐数量最多 3 个。

2. 类别导航模块化：
- 为“崇德讲堂”“朋辈导师”“晨曦晨读”分别展示该类型的热门与最新活动。
- 提供“更多热门/更多最新”跳转，进入列表页并自动选中该类别与对应排序；同时开启“只看当前可报名”。

3. 本轮新增性能与列表体验优化：
- “活动广场”列表改为分页展示，每页 5 条。
- “往期回顾”列表改为分页展示，每页 5 条。
- 两个列表的分页彼此独立，切换页码互不影响。
- 两个列表中的海报与推文图片启用懒加载，减少首屏图片加载压力。
- 搜索、分类、只看可报名、排序变化后，“活动广场”自动回到第一页。

4. 现阶段不实现（规划项）：
- 后端真分页与按条件服务端筛选。
- 更高级的推荐策略（点击/浏览历史、时间段偏好）。
- 高级搜索（拼音、模糊匹配、组合检索“导师名+时间段+地点”）。
- 轮播交互加强（parallax、分层视差、滚动过半引导）。

## 技术实现与约束

- 前端：在 `frontend/src/views/Activities.vue` 中新增分页状态、分页切片计算和 `el-pagination`。
- 懒加载：在“活动广场”和“往期回顾”使用 `el-image` 的 `lazy` 模式，避免一次性加载全部可见区外图片。
- 兼容性：保持现有 Timeline、智能推荐、类别模块、搜索筛选和报名流程不变。
- 本轮不新增依赖，不改动现有接口契约。

## 验收标准（可测试）

1. 活动广场：
- 每页固定显示 5 条。
- 当活动数大于 5 时出现分页器。
- 搜索、筛选、排序变化后自动回到第一页。

2. 往期回顾：
- 每页固定显示 5 条。
- 当回顾数大于 5 时出现分页器。
- 翻页不影响活动广场当前页。

3. 懒加载：
- 活动广场和往期回顾中的图片不再首屏一次性全部请求。
- 切换分页时仅加载当前页图片。

4. 兼容性：
- Timeline、推荐模块、类别模块、报名流程、查看详情、查看推文不受影响。
- 页面诊断无报错。

## 边界与不确定性已解决

- 本轮优先解决列表渲染与图片加载压力，不把现有整页数据流改成后端真分页，以降低回归风险。
- 若后续活动总量显著增加，下一阶段再将“活动广场/往期回顾”切换到服务端分页。
