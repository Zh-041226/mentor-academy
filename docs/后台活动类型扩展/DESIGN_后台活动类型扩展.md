# 后台活动类型扩展设计

## 总体方案

采用“预设类型 + 历史类型 + 直接新增”的轻量方案：
- 前端表单使用 `el-select` 的 `filterable + allow-create`。
- 后端新增历史类型接口 `/api/admin/activities/categories`。
- 保存时继续写入活动表的 `category` 字段，不新增表结构。

## 前端设计

1. 固定预设类型：
- 崇德讲堂
- 朋辈导师
- 晨曦晨读
- 其他

2. 历史类型：
- 页面初始化时从后端读取。
- 与预设类型去重合并后展示。

3. 新类型输入：
- 管理员可直接在选择框输入。
- 提交前做基础规范化：去首尾空格、压缩多余空白。

## 后端设计

1. 规范化：
- `normalizeActivityCategory()` 统一处理类型文本。

2. 历史类型接口：
- 从 `activity.category` 中提取全部非空值。
- 去重后按最近活动优先返回。

3. 创建/更新：
- 创建与更新都使用统一规范化后的类型值。

## 风险控制

- 本轮不引入单独类型表，减少迁移成本。
- 若未来需要权限治理、排序、禁用类型，再升级为独立类型管理模块。
